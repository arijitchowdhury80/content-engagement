## Method

1. Open `https://www.algolia.com`, trigger the overlay. Screenshot the pre-query state.
2. Enumerate **source filters**. WU-05 found 8 named content sources in the site's own
   taxonomy — Documentation, Support, Blog, Website, Developers, Resources, Academy,
   Customer Stories. Confirm against the live overlay and record each one's result count.
3. Capture each state, screenshotting every one:
   pre-query · typing/autocomplete · post-query results · AI-mode answer · zero-result.
4. Record **result groupings** — how results cluster, and by what attribute.
5. Record **result metadata** shown per hit (title, breadcrumb, type badge, snippet, date?).
   Note specifically whether the overlay displays a breadcrumb — the *pages* have none,
   so if the overlay synthesises one, that is a finding worth its own line.
6. Record **expansion paths**: "show more", per-source drill-in, full results page.
7. Record the **AI-mode prompts** and whether answers are cited, extractive, or generative.
8. Note what the overlay does *not* do — the gaps the concept must close.
9. Map each of the 8 non-negotiable journeys: can the current overlay complete it today?
   This is the table WU-25 will measure against.

## The journey scoring rubric — agreed 2026-08-07 (Arijit)

Fixed before the run so the table is a measurement, not an opinion. WU-25 scores the
new concept with this same rubric or the comparison is meaningless.

| Verdict | Rule |
|---|---|
| **PASS** | the journey's canonical destination is result **#1** |
| **PARTIAL** | it is in the **top 5** |
| **FAIL** | anything else — lower than 5, reachable only by filtering, or not in the index |

Mechanical note: the overlay renders **3 results by default**, so positions 4–5 require one
"Show more results" click. Score by rank position, not by what is on screen, and record
the click cost separately.

Each journey is probed with **one query, and that query is the nav label itself** — the
concept's claim is that search can replace the navigation, so the nav label is the fair
test. Record the exact query, the top 5 URLs in order, and the rank of the canonical
destination. If a destination lives off the search corpus (Login, /doc), that is a FAIL
with the reason stated, not an excuse.
