## What this unit is, and is not

The archive framed `[WU-26.1]` as an *"executive concept board for approval."* That framing was
struck in WU-01. This is **the frame around a live demo**, not a request for permission.
The demo is the argument; these artifacts point at it.

**The five-minute talk track drives the live demo rather than narrating slides.** If the
talk track works without the demo running, it is the wrong artifact.

## Method

1. `[WU-26.2]` Convert research findings into visual and interaction requirements.
2. `[WU-26.3]` Final routes and states — reconcile against what WU-21/22 actually shipped, not
   what WU-16 specified. If they diverged, the built version is the truth.
3. `[WU-26.4]` Copy and **sample queries.** These are load-bearing: the demo lives or dies on
   the queries chosen. Pick queries that are honest — ones that work because the system
   works, not ones reverse-engineered to hide gaps. Include at least one hard query and
   show the zero-result state deliberately. A demo that only shows happy paths reads as
   rehearsed and invites the question you least want.
4. `[WU-26.5]` Prototype success criteria — restate the 7 acceptance criteria with each marked
   met / not met / partial, citing the artifact that proves it.
5. `[WU-26.1]` **The one-page concept frame.** One page. What it is, why now, what the demo
   shows, what it would take, what could go wrong. The case-against gets a named section
   on this page, not an appendix.
6. **Five-minute talk track.** Beat by beat, tied to on-screen actions: which query to type,
   which state to show, what to say over it, what to do when someone interrupts. Include
   the answers to the five standing objections — SEO, conversion, accessibility, latency,
   safety — each in two sentences, each pointing at the artifact that backs it.
7. Acceptance criterion 7 check: **every objection has a written answer on disk.** Walk the
   five objections and confirm each resolves to a real file. Any that does not is a gap to
   close or to state.
