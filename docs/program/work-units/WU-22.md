## The constraint that defines this unit

**Frame 2 shares WU-20's index and WU-21's components.** Acceptance criterion 4 is
explicit: both frames on one index. If Frame 2 needs a different index, the concept has
failed a criterion — escalate rather than building a second index quietly.

Component reuse is also the argument, not just efficiency: if the north-star frame and the
near-term wedge are built from the same parts, that is evidence the wedge is a real step
toward the destination rather than a different product. Say that in WU-26's talk track.

## Method

1. Read `42-frame2-search-first.md`. Frame 2 is the destination: search-led as the primary
   navigation mechanism, not an enhanced overlay.
2. **Reuse Frame 1's components.** Extract shared components into a common module rather
   than copying files — a copy will drift, and two drifting copies of a demo component is
   the same rot problem as duplicated data.
3. Implement the same five states, with Frame 2's more aggressive posture.
4. Same 8-journey test must pass. `[WU-15.7]`'s "how much conventional nav must remain" answer
   from WU-15 is likely *lower* here than in Frame 1 — but Login and Contact Sales still
   need persistent access. An enterprise buyer will not search for "login."
5. Same accessibility and mobile bar as WU-21. Frame 2 leans harder on search, which makes
   keyboard and screen-reader support *more* load-bearing, not less.
6. Make the difference between the two frames legible. If a reviewer cannot tell in ten
   seconds why these are two frames rather than two drafts, the concept is not landing.
