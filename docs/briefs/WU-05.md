## The six axes

Every record gets a value on all six. Closed vocabularies, defined in WU-04.

| # | Axis | Example values |
|---|---|---|
| 1 | visitor intent | evaluate · implement · learn · troubleshoot · buy · compare |
| 2 | audience | developer · marketer · merchandiser · exec · existing customer |
| 3 | business context | ecommerce · B2B · media · marketplace · SaaS · docs |
| 4 | product capability | search · recommend · neural/AI · merchandising · analytics · agents |
| 5 | content type | product page · doc · blog · case study · pricing · webinar · ebook |
| 6 | conversion action | demo · signup · contact sales · read · download · login |

⚠ **Do not copy the facet vocabulary from `AC2_WWW_MULTI_NEURAL`.** Its
`facets.facet0-5` slots look like six axes but hold blog/docs taxonomy (blog category,
vertical, framework, language, integration, "supported") and are only 0.6–14% populated.
Verified 2026-08-05. Named here because the resemblance is a trap.

## Method

1. Load `ia-map.json`; freeze the six value vocabularies. Write them down before classifying.
2. Classify all 2322 records. Batch by `page_type` cluster — a `code-exchange` record and
   a `press-release` do not need the same reasoning. 272 code-exchange records classify
   almost identically; exploit that.
3. Allow multi-value where honest (a page can serve developer *and* marketer). Decide
   single- vs multi-value **per axis** and record the decision — it becomes the Algolia
   facet type in WU-15.
4. Every record must carry all six axes. Use an explicit `unknown` value rather than a
   null, so coverage is measurable instead of silently sparse.
5. Emit the **facet schema** WU-15 consumes: attribute name, single/multi, and whether it
   needs `searchable()` or `afterDistinct()`.
6. Spot-check: sample 20 records across clusters and hand-verify all six axes. Record
   the observed error rate. An unstated error rate on a Haiku-tier bulk pass is not a result.
