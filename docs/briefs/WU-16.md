## Skill routing — required, not optional

Per the standing routing rule, any frontend page goes through **`frontend-builder`**,
never `frontend-design` directly. `frontend-builder` runs the design-thinking workflow
first, then calls the design engine. It will pull in **`algolia-design`** (palette, type,
UI kit) and **`artifact-design-arijit`** (Sora typography, house tokens, WritingSOPs copy
rules). Announce the routing before starting.

## Method

1. Read `41-frame1-cmo-wedge.md` and build what it specifies. This unit implements a
   decision already made — if the spec is ambiguous, fix the spec, do not improvise.
2. Wire against the **live WU-15 index**. Zero fixtures. If a query returns nothing, that
   is an index or ranking bug to fix in WU-15, not a reason to hardcode a result.
3. Implement all five states from WU-11: pre-query · autocomplete · post-query ·
   navigational (direct-hit) · zero-result/ambiguous.
   The **navigational** state is what makes the "faster than today" claim true — a user
   typing "pricing" must land on pricing, not on ten results about pricing.
4. All 8 journeys **reachable within one interaction**. That is the DoD, and it is stricter
   than "reachable." One interaction = one query, or one click from the pre-query state.
5. Keep the must-preserve destination list (WU-04) intact — real URLs, real addressability.
6. **Mobile is not a later pass.** Acceptance criterion 5 is a hard requirement and
   retrofitting a search-led layout to mobile is a rewrite. Build responsive from the start.
7. Accessibility: WU-10 `[56]` establishes the current site has no landmarks. Do not repeat
   that. Real `<main>`, real landmarks, focus management on the search surface, keyboard
   path to every journey, live-region announcements for result updates.
8. Do not fake the agentic layer. WU-14 `[9]` decided its role; honour that decision
   including its on-screen labelling.
