## Method

1. **`[13]` Complete taxonomy.** Top-level nav, subnav, page types, CTAs, audiences,
   use cases, product concepts, resource types.
   - Page types and CTAs come from the corpus (`page_type`, `cta.text` distributions).
   - **The mega-menu does not.** It is site chrome and WU-02 strips it from every record
     by design. Extract it once from the homepage DOM — that satisfies source task `[18]`
     as a standalone artifact. Products, Solutions, Developers, Resources menus.
2. **Re-type the 57 `other` records.** These are paths the URL-based classifier could not
   type. Read their titles/bodies and either assign a real type or create one.
3. **`[14]` Repeated IA patterns** across product / solution / industry / comparison /
   docs / pricing / contact-sales / customer-proof / resources / partners / company pages.
   Use `body` structure, not just URL shape.
4. **`[15]` Intent per page.** Work at the page-type-cluster level, not 2322 times.
   Assign intent per cluster, then spot-check ~5 records per cluster against the body.
5. **`[16]` Page role:** SEO-acquisition vs conversion vs trust-building. Note that
   1086 blog-posts + 358 resources = 62% of the site is plausibly acquisition — if so,
   say it plainly, because it is the core of the SEO objection WU-10 has to answer.
6. **`[17]` The tension.** Compare the explicit nav taxonomy against the implicit
   search-source taxonomy (the 8 sources: Documentation, Support, Blog, Website,
   Developers, Resources, Academy, Customer Stories).
   **Name it AND resolve it.** The plan is explicit that observing it is a fail.
7. **Must-preserve destination list.** Every URL that cannot lose its addressability —
   SEO entry points, deep links in the wild, anything in docs or email. This list is
   the contract WU-16/WU-17 must not break and WU-10's SEO answer leans on.
