## Method

1. Define the **interaction scorecard first**, before visiting anything, so all four
   agents score on identical axes. Suggested: entry affordance · pre-query state ·
   autocomplete richness · result grouping · faceting · zero-result handling ·
   AI/answer layer · citations · keyboard support · mobile · time-to-destination.
2. Each agent visits its targets, screenshots, scores.
3. **Every pattern claim carries a URL.** A claim without a URL does not enter the doc.
4. Build the **component inventory** — the reusable UI parts these patterns are made of.
   WU-16 turns this into the state/component model and WU-21 builds from it, so name
   components concretely (`prompt-chip`, `source-tab`, `answer-panel-with-citations`)
   rather than describing them in prose.
5. Note explicitly which patterns are **B2B/SaaS** vs **ecommerce**. The concept is for a
   B2B marketing site; borrowing an ecommerce pattern without naming the transfer risk is
   exactly what WU-15's case-against will attack.
6. Score algolia.com's current overlay on the same card. If it already beats some
   references, that strengthens the thesis and belongs in WU-26's talk track.
