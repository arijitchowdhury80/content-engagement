## Method

**Translation `[WU-11.1]`–`[WU-11.3]`**

1. `[WU-11.1]` Each top-level nav category → candidate search affordances. Products, Solutions,
   Developers, Resources, Pricing, Customers, Company. For each: does it become a facet,
   a chip, a promoted module, a suggestion, a result category, an answer panel, or a
   persistent utility link? One nav item may map to several.
2. `[WU-11.2]` Convert the current overlay's elements into homepage-level architecture. The
   overlay already has source tabs, AI-mode prompts, suggestions, groupings — this is
   mostly a promotion exercise, so state what changes when it moves from modal to page.
3. `[WU-11.3]` The classification decision, per IA element, into exactly one of:
   facet · chip · promoted module · suggestion · result category · answer panel ·
   persistent utility link. **Login and Contact Sales almost certainly must be persistent
   utility links, not search results** — an enterprise buyer will not search for "login."
   If the model makes them searchable-only, the model is wrong.

**The five states `[WU-11.4]`–`[WU-11.8]`**

4. `[WU-11.4]` **Pre-query homepage.** What does a first-time anonymous visitor see with an
   empty query? This is the highest-stakes screen in the project — it replaces the
   current homepage and it is what a CMO reacts to in the first three seconds. Specify
   the promoted modules, the prompt chips, the trust signals, and what conventional nav
   survives (WU-10 `[WU-10.7]` gives the proportion).
5. `[WU-11.5]` Autocomplete. Suggestions, categories, direct destinations, keyboard model.
6. `[WU-11.6]` Post-query results. Grouping, faceting, ranking, answer panel placement.
7. `[WU-11.7]` **Navigational query.** Someone types "pricing." They want the pricing page,
   not ten results about pricing. Define the direct-hit / best-bet behaviour explicitly —
   this is the state that makes or breaks the "faster than today" claim in criterion 3.
8. `[WU-11.8]` **Zero-result and ambiguous intent.** The plan flags this as the state most
   likely to be skipped and most likely to be attacked in a live demo. Write it fully:
   what shows, what is suggested, how the user recovers, and what happens on a
   competitor's name or a hostile query.
9. Produce a **query-intent taxonomy** — the query classes the system must recognise
   (navigational, informational, comparison, transactional, support, developer) and the
   state each routes to.
10. Trace all 8 journeys through the state model. Any journey that cannot complete is a
    model defect, not a journey to drop.
