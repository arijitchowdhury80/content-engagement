## Method

1. Pick an index name that cannot be confused with anything on this shared 146-index
   account, and that won't be mistaken for `Algolia_Prod_Copy_*`. State it in the Asana
   comment. A prior version of this demo used `SEARCHFIRST_WWW_v1` — that index and its
   crawl-derived data are gone; pick a fresh name (e.g. `SEARCHFIRST_WWW_v2`) rather than
   reusing it, so there's no ambiguity about which build a query result came from.
2. Query `Algolia_Prod_Copy_Enhanced` filtered to `environment:"prod20260722" AND
   language_code:"en"`. **Report the exact count from the API.** This replaces the old
   "join corpus to six-axis classification" step entirely — Chapter 1's axes are already
   on the source records, there's nothing to join.
3. Transform to `index-schema.json`. Set `objectID` deterministically from the source
   `url` so re-indexing is idempotent rather than duplicating.
4. Body strategy: **there is no body to split or truncate.** Records carry `abstract`/
   `description` only. Use those directly as the snippet/summary field. Do not fabricate
   longer text. State this plainly in the index-build-report — it's a real, temporary
   limitation, not a bug to hide.
5. Push records. Configure settings: searchable attributes, Chapter 1's 8 facets (plus
   WU-05's 3 new axes if they've landed by then — check before assuming), custom ranking,
   `mode: neuralSearch`.
6. Exclude junk from the demo index: `is404:true` records (24 on Enhanced, already
   flagged), and anything outside the `prod20260722`/`en` filter. **Say what was excluded
   and why**, with counts from the API.
7. **Verify with real queries, not a record count.** Run the navigational queries the demo
   depends on — "pricing", "shopify", "how do I integrate", plus one per journey — and
   confirm the right page comes back first.
