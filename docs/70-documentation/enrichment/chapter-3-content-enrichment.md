# Chapter 2 — Content Enrichment

> **Status: not started.** Scope defined below; no work performed.

## Why this chapter exists

[Chapter 1](./chapter-1-taxonomy-enrichment.md) hit a ceiling that no amount of rule-writing can lift.

`Algolia_Prod_Copy_Enhanced` has **no body field**. Total natural language across the whole index is **6.37M characters over 12,114 records — 526 characters per record.** A title and roughly one sentence.

> **Re-measured 2026-08-06 after deduplication.** Was 7.41M chars over 16,967 records (437/record).
> Dedup removed 4,853 duplicate records carrying **1.04M characters — 14.0% of the index's text was
> literally the same text stored again.** Chars-per-record rose only because the denominator shrank;
> no new content was added and the conclusion is unchanged. If anything it is sharper: 526 characters
> is still a title and one sentence, and the real body text still does not exist.

Median text by page type:

| page_type | median chars |
|---|---|
| `doc-rest-api` | 117 |
| `doc-api-reference` | 160 |
| `doc-guide` | 203 |
| `press-release` | 217 |
| `developer-code-sample` | 308 |
| `blog-post` | 370 |
| `resource` | 439 |
| `case-study` | 490 |
| `support-article` | 1,077 |

The measured consequence: `product` resolves at 42.5% against a 70% target, `feature` at 73.6% against 75%. Every URL-derived signal has already been mined — 89 rules, SDK method groups, 194 API parameters. The residue needs page text that does not exist in the index.

## The opportunity, already measured

**51.8% of the index's 12,114 distinct URLs already have a real body** sitting in other indices in the *same Algolia app*, or in local corpus files on disk. Zero fetching required.

**Re-measured 2026-08-06** after the two local corpus files (`records.jsonl`,
`records-doc.jsonl`) were deleted from disk and scrubbed from git history. They turned out to be
**fully redundant** with the live indices — total coverage is unchanged.

| Source (all live Algolia indices, same app) | URLs it covers |
|---|---|
| `SEARCHFIRST_WWW_v1` | 3,775 |
| `algolia-central_enterprise_ledger` (excluding `/old-docs/`) | 3,302 |
| `AC2_WWW_MULTI_NEURAL_body` | 3,037 |
| **Union, distinct** | **6,274 / 12,114 = 51.8%** |

The three overlap heavily, which is why the union is far below the sum. Nothing needs to be
crawled to reach 51.8% — it is three API reads.

> **Check before relying on this.** `SEARCHFIRST_WWW_v1` contributes the single largest share.
> The repo `CLAUDE.md` states it was deleted; the account still showed **4,196 entries** on
> 2026-08-06. Confirm it exists before planning around it — if it is removed, re-measure, because
> the ledger and AC2_body do not fully cover what it holds.

Median body over the covered set is 10,039 chars. Index growth roughly +49 MB at a 12,000-char cap.

**Remaining gap: 5,838 URLs.** English 3,044 (Documentation 2,440, Support 326, Academy 142, Website 91, Blog 40), French 1,397, German 1,397.

Crawling is viable where needed — a prior run fetched 4,207 pages at 2.9 pages/sec with zero failures, and the WAF risk flagged early in the project never materialised. `support.algolia.com` has a Zendesk Help Center API and needs no crawl at all.

## Explicitly rejected

**Remapping `algolia-central_enterprise_ledger`'s `/old-docs/` URLs onto `/doc/`.** Decided against by Arijit on 2026-08-05. The remap would have covered 2,341 of the 2,440 Documentation-gap URLs and validated at 96.6% on title match — but it is not to be revisited without a new decision.

## Scope to define

- Where body comes from per URL, and precedence when several sources have one
- Body length cap, and its effect on index size
- Whether `abstract` is regenerated by extraction from body — decided earlier: **extraction, never LLM-generated**
- Whether fr/de records get bodies at all. An English body on a French record is wrong, and locale-twin inheritance does not work for prose the way it does for tags
- Re-running Chapter 1's classifier once bodies exist. `product` and `feature` should lift materially, and `taxonomy_version` makes the whole corpus the work queue automatically

## What this unblocks

Higher `product` and `feature` coverage. Snippeting. And grounded answer synthesis by agents — today they can only route users to pages, because there is no text to synthesise from.
